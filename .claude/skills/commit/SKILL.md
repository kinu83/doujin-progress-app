# commit

## 手順

1. `git status` と `git diff`（ステージ済みなら `git diff --staged`）で変更内容を確認する。
2. 関係のない変更が混ざっていないかを見る。混ざっていれば、どう分けるかを提案する。
   - 例：`.firebase/hosting.*.cache` はデプロイで更新されるファイルなので、機能の変更と一緒にコミットしない。
3. 下の形式でコミットメッセージを作る。
4. コミットするファイルの一覧とメッセージをユーザーに見せ、承認を得る。
5. 承認されたら、対象のファイルだけを `git add` してコミットする（`git add -A` や `git add .` は使わない）。
6. `git log -1` で結果を確認して報告する。

## コミットメッセージの形式

- `種別:日本語の要約`（コロンのあとにスペースを入れない）
  - 例：`feat:タスクの期限表示を追加`
- 種別は次のどれか
  - `feat`：機能の追加・変更
  - `fix`：バグ修正
  - `docs`：ドキュメントのみの変更
  - `style`：見た目・フォーマットのみの変更（動作は変わらない）
  - `refactor`：動作を変えずにコードを整理
  - `chore`：設定・依存関係・スクリプトなどの変更
- 要約は1行で、「何をしたか」が分かるように書く。本文は不要。

## 注意点

- コミットの実行前に、必ず内容をユーザーに見せて承認を得る。承認は1回ごとに取り、「前にOKをもらったから」と次のコミットまで進めない。
- main ブランチ上ではコミットしない。main にいる場合は、先に `feature/機能名` のブランチを作るよう提案する。
- `.env` など秘密情報を含むファイルはコミットしない。
