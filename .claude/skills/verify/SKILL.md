# verify

## 手順

1. `npm run typecheck` を実行する。エラーがあれば先に直す。
2. `npm run build` を実行する。
3. `npm run dev` をバックグラウンドで起動する（http://localhost:3000）。既に起動している場合は再利用する。
4. 変更した画面を開いて確認する。ブラウザ操作のツールが使える場合はそれで確認し、使えない場合は確認してほしい手順をユーザーに伝える。
   - `/`：プロジェクト一覧・修羅場レベル
   - `/projects/<id>`：プロジェクト詳細・ページ進捗
   - `/calendar`：カレンダー・作業の割り当て
   - `/settings`：作業工程・修羅場レベルの基準・アカウント
   - `/terms`：利用規約・プライバシーポリシー
5. ブラウザのコンソールと、開発サーバーのログにエラーが出ていないかを確認する。
6. 確認が終わったら開発サーバーを停止する。
7. 結果を「確認できたこと」と「未確認のこと」に分けて報告する。

## 注意点

- `/terms` 以外の画面は Google ログインが必要（未ログインではログイン画面が表示される）。Claude はログインできないため、ログイン後の画面はユーザーに確認を依頼し、自分で確認できたとは書かない。
- 開発サーバーも本番と同じ Firestore につながる。確認のためにデータを作成・削除するときは、ユーザーの実データを消さないよう、事前に何をするかを伝える。
- 確認結果は pr の「動作確認」にそのまま使う。実際に行っていない確認は書かない。
- `.env` は読まない。環境変数が足りずに起動できない場合は、ユーザーに伝える。
