# issue

## 手順

1. 何を解決したいのかを会話から整理する。足りない情報があればユーザーに聞く。
2. 関連する Issue・PR を `gh issue list` / `gh pr list` で確認し、背景に紐付ける。
3. 下の形式でタイトルと本文を作る。
4. タイトル・本文をユーザーに見せ、承認を得る。
5. 承認されたら、本文を一時ファイルに書いて実行する。
   - 作成：`gh issue create --title ... --body-file ...`
   - 更新：`gh issue edit <番号> --body-file ...`（更新前に `gh issue view <番号>` で今の本文を読み、変える部分を伝える）
6. Issue の URL を報告する。

## タイトル

- コミットメッセージと同じ `種別:日本語の要約` の形式にする（例：`chore:開発作業用のSkillsを追加する`）。種別は commit Skill の一覧に合わせる。

## 本文

```markdown
## 目的
- 解決したいことをわかりやすく書く（1〜2文程度）

## 背景
- 背景を書く。必要に応じて箇条書きにしたり、関連するIssueやPRを紐付ける

## 設計方針
- 設計方針を検討する。懸念点があれば記述する。

## 最終的な成果物
- 最終的にどのような動作をするようになるか、成果物を書く
```

## 注意点

- 作成・更新の実行前に、必ず内容をユーザーに見せて承認を得る。承認は1回ごとに取り、「前にOKをもらったから」と次の実行まで進めない。
- 懸念点は、できるだけ解決策や方針とセットで書く。
